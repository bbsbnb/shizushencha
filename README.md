# 建筑项目施组审查助手

无需登录的施工企业内部网页工作台。支持项目建档、文件版本、分块续传、PDF/Office解析、16项审核规则、受控规范、Agnes模型审核、原文对照、技术复核、Word报告和整改复审。

## 启动

要求 Python 3.11+。Windows PowerShell：

```powershell
cd <本项目目录>
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

浏览器打开 http://127.0.0.1:8765。首次启动创建虚拟环境并安装 `requirements.txt`。已有依赖环境也可直接执行：

```powershell
python -m uvicorn app:app --host 127.0.0.1 --port 8765
```

如需公司内网访问：`start.ps1 -Bind 0.0.0.0 -Port 8765`，再按公司网络配置开放访问。系统没有账号及角色权限，所有可访问者共享所有项目和操作；姓名为自行填写，不是身份认证。

## 接入 Agnes

点击网页右上角“模型配置”，填写 API 地址、模型名称和 API 密钥，点击“测试连接”，再“保存配置”。地址与模型已预填 Agnes 默认值。保存后立即生效，无需重启；已有密钥不回显，留空保留，输入新密钥可替换。连接测试仅发送简短消息，不上传工程资料。

也可以将 `.env.example` 复制为 `.env`，在本机编辑：

```dotenv
MODEL_BASE_URL=https://api.agnes-ai.cn/v1
MODEL_NAME=agnes-3.0-flash
MODEL_API_KEY=在本机填写真实密钥
```

服务端按 OpenAI 风格 `/chat/completions` 协议调用，已有密钥不回传网页。保存后点击等待配置任务的“重试审核”。支持超时和输出长度配置；服务商的协议兼容性与真实审核效果须用可用密钥实测。未配置时保留任务为“待配置模型”，不生成模拟问题、不虚构审核通过。

长文按约2万字符一批处理，可能产生多次模型调用；发起前网页有提示。局部批次保留检查点；显式重试继续未完成批次。服务重启后等待中或中断的任务标为失败供手工重试，避免自动重复付费调用。

## 使用顺序

1. 建立项目，选择历史复核或当前报审，填写审核基准日期和项目技术负责人。
2. 上传施工组织设计。首次试点使用《西安一中施工组织设计.pdf》，历史基准暂按2020-11-24录入，并由技术人员核实实际适用条件。原件与各版本保存在服务器。文件行右侧可删除版本，删除前需确认。已被审核引用的文件从项目资料列表移除，原件及解析内容保留供历史审核查阅；未引用文件永久清理。删除后不能用于新审核，正在解析或参与运行中审核的资料须待处理结束后删除。操作日志记录删除人、文件版本和历史保留情况。
3. 等待后台解析，查看失败页和需原页核对的内容。PDF页序是定位依据；扫描文字和技术数字不能仅凭OCR作确定性结论。
4. 在受控规范库录入有可靠来源的规范条文、实施日期、过渡条件和核验人；待核验资料可通过“编辑 / 核验”补全并更新状态。只有已人工核验且符合任务日期范围的规范参与检索；初始库为空，不含未经核验的法规文本。
5. 发起审核，明确主文件、补充资料与已确认工程事实。审核任务快照保留文件、模型、提示词、规则及规范版本。
6. 对照原文逐条采纳、修正或驳回意见，必要时人工补充问题。完成后确认内部报告，下载Word。
7. 上传新的整改版，选择已确认任务作为基线。系统对旧问题建议复审状态并识别新问题，人工逐项确认，历史版本保持不变。

图纸只辅助核对设计说明及可可靠识别的参数；Excel只核对范围和项目特征。没有上传图纸、清单、合同或勘察资料时不宣称完成相关交叉核对。

## 解析与可选工具

- PDF：文字层提取、扫描图页预览；低文字量页面尝试调用本机Tesseract中文OCR。需安装Tesseract及 `chi_sim`、`eng` 语言包；可用 `TESSERACT_CMD` 指定可执行文件。未装时显示待核对，不伪造识别结果。
- DOC/DOCX：优先使用已安装LibreOffice或Windows WPS转为固定版式PDF。旧DOC无转换器时报明确错误。DOCX没有转换器时以原文块定位，不能当作物理页码。
- XLSX/XLS：按工作表、单元格或行分块，公式不执行。含公式的参数需要人工核实。

## 实现与边界

- 单机 FastAPI + 原生JavaScript网页 + SQLite（WAL）+ 本地文件持久化。该实现采用最小依赖完成可运行版本，未采用需求文档中建议的Vue/PostgreSQL；后者不是用户指定技术栈。数据位于 `data/`，整目录可在停服后备份。
- 后台线程池与数据库任务状态；单实例运行，不要用多个Uvicorn worker。后续多人高并发部署再迁移PostgreSQL、独立任务队列及对象存储。
- 16项基础检查清单不是完整专业规范库。规范通过人工粘贴来源文本录入；尚无自动联网更新、规范PDF批量导入、专业规则在线编辑或15+专项完整覆盖。
- 证据校验验证摘录是否真实出现在来源，不能代替专业适用性判断。扫描文字层的问题自动提示人工原页确认；无法核验的违规依据降为待核实。
- 整改复审使用新版本的相关片段检索，不把“找不到原句”认定为已解决；仍需技术人员确认。
- 本次交付是可运行的首轮实现，未完成真实云端模型准确性、全量规范合规和生产性能验收。没有用测试数据冒充真实专业审核成果。

## 检查

```powershell
python -m unittest discover -s tests -v
```

测试使用隔离临时数据库及假的模型响应，只检验流程与证据防护；不调用真实云端模型。应用日志和报告均不包含API密钥。

规范编辑仅影响后续新审核，已创建任务保留当时的规范快照。连续多轮复审会继承上一轮尚未解决的历史问题；总览待整改数仅采用已确认复审的最新结果。进程环境变量优先于 `.env`，以环境变量部署时需在进程配置处修改相应模型参数。
